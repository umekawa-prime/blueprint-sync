# モバイル移管（ファイル共有でデータを持ち出せる）

日付: 2026-09-06  
対象: Blueprint Sync  
前提: デスクトップ（Windows / Tauri）にある編集・プロジェクト・同期機能を、Android / iOS でも同じアプリとして使えるようにする。モバイル上のプロジェクト実体は、OS のファイル共有で他端末・デスクトップとやり取りできる。

## 背景

いまの完成度が高いのは Windows デスクトップである。Android / iOS はビルド経路とカメラ用 Info.plist はあるが、プロジェクトはフォルダ選択前提のため起動画面から先へ進めない。現場ではタブレット／スマホで図面を開き、写真をピンし、事務所の PC や別端末へデータを渡したい。クラウド常時同期は前提にしない。オフラインのまま、OS 標準の共有シート・ファイルアプリ・AirDrop / Nearby Share / メール / LINE などでプロジェクト一式を渡す。

## ゴール

- デスクトップにある機能を、描画エンジンを書き換えずにモバイルへ移す
- 起動後はプロジェクト必須（新規作成または既存を開く／取り込む）
- プロジェクトの実体はデスクトップと同じフォルダ構成を保つ
- モバイルのプロジェクトは「プロジェクト一式」としてファイル共有できる（書き出し・受け取り）
- 共有した一式をデスクトップでフォルダとして開ける。逆も同じ
- LAN 同期（ホスト／クライアント）も残す。永続的な持ち出しの正はファイル共有とする

## やらないこと

- 別言語・別 UI フレームワークへの全面書き換え
- クラウドアカウント必須の同期（OneDrive ログイン、専用サーバ、常時バックアップ）
- 注釈のタイマー自動保存（既存どおり、切替・閉じる・保存時に書く）
- `pdfRenderer.ts` / Fabric 描画本体 / `pdfCoords.ts` の座標計算の再発明
- 写真ピンを PDF 画素へ焼き込む変更（ピンは注釈 JSON のまま。共有パッケージに含まれる）
- アプリ再起動後のタブ復元（既存タブ仕様を維持）
- 消しゴム新設、ペン仕様の作り直し

## 互換の原則

データ形式を変えない。モバイルは「フォルダを選ぶ」代わりに「アプリ管理領域に同じ木を持つ」だけである。

```text
<プロジェクト根>/
  図面/
  工程表/
  <レガシー直下 PDF>
  .blueprint-sync/
    project.json
    annotations/
      図面__1F平面図.pdf.json
```

- `project.json` / 注釈 JSON / PDF 配置 / 注釈ファイル名（`/` → `__`）は現行どおり
- 写真ピンは `photoPins` 内の JPEG data URL（本体 最大辺 1600px、サムネ 96px）
- 保存で PDF に焼き込むのは Fabric 上の線・文字だけ。ピンは JSON 側
- デスクトップがこの根フォルダを開けば、モバイルと同じ図面・注釈・ピン・リンクが見える

## データの置き場（モバイル）

OS のフォルダピッカーを必須にしない。サンドボックス内にプロジェクトを置く。

```text
{appDataDir}/projects/{project.id}/
  …上記と同じ木…
```

- `project.id` は既存 `project.json` の UUID
- 表示名は `project.json` の `name`
- 最近使った一覧は `{ id, name, path }`。`path` はサンドボックス上の根。消えていたら一覧から外す（最大 8 件）
- 端末の「ファイル」アプリから見える場所に出せるかは OS 依存。正本はアプリ管理領域とし、外へ出すときは必ず共有パッケージを作る

デスクトップは現行どおりユーザーが選んだフォルダが正本。モバイルのサンドボックスパスをデスクトップが直接読むことはない。橋はファイル共有だけである。

## ファイル共有

モバイルのデータの出入り口は OS のファイル共有である。LAN は現場その場のライブ同期用。

### 共有単位

1. **プロジェクト一式（正）**  
   プロジェクト根を ZIP にした 1 ファイル。中に必ず `.blueprint-sync/project.json` がある。
2. **図面 1 枚（補助）**  
   いま開いている PDF（保存済みバイト）。注釈 JSON やピンは含まれない。ピンごと渡すなら一式を使う。

### パッケージ形式

- 拡張子: `.bpsync.zip`
- 中身: プロジェクト根のファイルを、根ディレクトリ名を付けずに格納する（ZIP 直下に `図面/`、`工程表/`、`.blueprint-sync/`）
- ファイル名: `{sanitizedName}.bpsync.zip`。`sanitizedName` はプロジェクト名からパス区切りと制御文字を除いたもの。空なら `project`
- ZIP 内に `__MACOSX` / ドット始まりセグメント / `..` を書いてはならない（既存 zip 取り込み規則と同じ）
- 受け取り判定: ZIP を展開して `.blueprint-sync/project.json` が読め、現行スキーマを満たせばプロジェクト一式。満たさなければ通常 ZIP（中の PDF を開いているプロジェクトへ取り込む）

カスタム拡張子だけにしない。相手アプリが ZIP として扱えることと、こちらの受け取り判定が両立する。

### 書き出し（共有する）

編集画面から「プロジェクトを共有」を出す。

1. 表示中プロジェクトの注釈をディスクへ書く。失敗したら共有しない
2. サンドボックス上のプロジェクト根を ZIP する
3. OS の共有シートに載せる（Android `ACTION_SEND`、iOS シェアシート）
4. 共有先（ファイルアプリ、AirDrop、Nearby Share、メール、チャット等）は OS に任せる

「この図面を共有」は、現在の PDF バイトだけを共有シートに載せる。未保存の Fabric 注釈を PDF に含めたい場合は、先に「保存」してから共有する。

### 受け取り（取り込む）

次をすべて受け付ける。

| 入り口 | 動作 |
|---|---|
| 共有シートでこのアプリを選ぶ | 添付が `.bpsync.zip` / 通常 ZIP / PDF なら下の規則 |
| ファイルアプリの「この App で開く」 | 同じ |
| アプリ内「取り込む」 | OS のファイル選択（HTML input またはプラグイン）。複数可 |

判定:

- **プロジェクト一式**: 新プロジェクトとして `{appDataDir}/projects/{id}/` に展開する。同じ `id` が既にあれば、上書きするかキャンセルする（黙ってマージしない）
- **通常 ZIP**: プロジェクトが開いていれば、中の PDF を図面／工程表へ取り込む（現行 zip 取り込み）。開いていなければ「先にプロジェクトを開くか、一式を共有してください」
- **単体 PDF**: 開いているプロジェクトへ追加。未オープンなら、その PDF 1 枚で新規プロジェクトを作るか、取り込みをやめるかを選ぶ

デスクトップとの往復:

- モバイル → デスクトップ: 受け取った `.bpsync.zip` を展開し、できたフォルダを「既存プロジェクトを開く」
- デスクトップ → モバイル: プロジェクトフォルダを ZIP して送る。根に `.blueprint-sync/project.json` があれば一式として開く。拡張子が `.zip` でも中身で判定する

### 容量

- 一式 ZIP の作成に失敗したら（ディスク不足、巨大な data URL）ステータスを出し、共有シートは出さない
- OneDrive 取り込みの 80 MB 上限はネットワーク取得だけ。ファイル共有の ZIP に同じ上限は設けない。ただし端末が拒否したらそのエラーを出す
- 写真ピンは JSON に埋め込まれるため、枚数が多いと一式が大きくなる。仕様上は許容し、ピン専用ファイル分割は今やらない

## 起動とプロジェクト

起動直後はプロジェクト画面だけ（キャンバスは出さない）。

- **新規作成**: 名前を入力する。フォルダ選択はしない。サンドボックスに木を作り、タブを 1 つ開く
- **既存を開く**: この端末のプロジェクト一覧（最近＋サンドボックス内）から選ぶ
- **取り込む**: ファイル共有／ファイル選択。上の受け取り規則
- **最近使ったプロジェクト**: タップで開く。実体が無ければ外す

「プロジェクトを閉じる」で起動画面に戻る。最後のタブを閉じたときも同じ（既存タブ仕様）。

デスクトップの「フォルダを選んで作成／開く」はデスクトップに残す。モバイルのホームには出さない。

## 画面（モバイル）

描画の見え方は変えない。chrome だけ端末幅に合わせる。

### 共通

- ウィンドウボタン（最小化／最大化／閉じる）と `data-tauri-drag-region` は出さない（既存 chrome 仕様）
- フォントは現行の Noto Sans JP Variable
- ステータス（エラー、未保存、接続）は残す

### 電話幅

- 左サイドバーは常時固定しない。ハンバーガーでドロワー
- ツールバーは下寄せ。よく使うもの（選択／ペン／テキスト／移動／保存／カメラ）を出し、ページ・ズーム・接続・共有はオーバーフローまたはシート
- プロジェクト切替はタブバーではなくシートまたは一覧。メモリ上のタブモデルは既存のまま（表示中だけ pdf.js / Fabric を動かす）
- 長押し 500ms で「画像を挿入／撮影」（既存）。ホバープレビューは出さない。ピンタップで小さなプレビュー、プレビューまたはピンの再タップでモーダル

### タブレット幅

- サイドバーを出せる（閉じてもよい）
- ツール類は上または下の 1 行に寄せてよい
- ピンはホバープレビュー＋クリックでモーダル（既存デスクトップ挙動）

## 移管する機能

デスクトップにあるものは、次の読み替え以外は同じ結果になること。

### 図面編集

- pdf.js 表示、ページ送り、ズーム 0.4–4（ピンチとボタン）、スクロール移動
- ツール: 選択 / ペン / テキスト / 移動。ペン色・太さパレット
- スタイラス: 筆圧、手のひら拒否（既存）
- テキスト: タップで `IText`、フォント Noto Sans JP Variable
- 履歴: 元に戻す／やり直し、最大 50。切替・閉じる失敗時は中断（既存）
- 保存: 開いている PDF を上書きし、注釈 JSON も書く。成功トースト

### 写真ピン

- 挿入（ファイル共有／ライブラリ）と撮影
- 正規化座標 `nx`/`ny`、注釈 JSON へ保存
- モバイルのカメラは背面（`environment`）を先に取る。USB カメラ優先はやめる
- 撮影許可は OS ダイアログ。iOS の利用目的文言は既存 plist を使う。Android はカメラ／メディア権限を capability とマニフェストに足す
- ピン削除 UI は今やらない（ストア関数はあっても出さない）

### PDF / ZIP の追加

- 図面へ追加、工程表へ追加
- 受け取りはファイル選択または共有。デスクトップのエクスプローラーダイアログは使わない
- 名前衝突はスキップして報告（既存）

### OneDrive リンク

- `project.json` の `links` は同じ
- タップで OS ブラウザ（opener）
- オンラインなら現行どおり共有 URL から PDF を取り込み（80 MB、名前衝突はスキップ）
- オフラインならブラウザ起動も取り込みも失敗メッセージ

### LAN 同期

プロトコルは変えない。`ws://`、ポート 7840、メッセージ型 `hello` / `request-pdf` / `pdf-meta` / `pdf-chunk` / `annotation` / `page`。チャンク 64KB。写真ピン・`project.json`・一式 ZIP は送らない。

- **ホスト**: モバイルでも待機できる。QR と `ws://IP:7840` を出す。画面を離すと OS がソケットを切ることがある。切れたら「接続が切断されました」（既存）。バックグラウンド常時ホストは今やらない
- **クライアント**: QR 読取（背面カメラ）または IP 手入力
- 接続はアプリ全体で 1 本。同期するのは表示中タブ（既存）
- ラベルは「ホスト」「クライアント」にする（Windows / Android 固定はやめる）

LAN で受け取った PDF は表示中プロジェクトのメモリ上に載る。端末に残すには保存する。現場を持ち帰る正本は、保存後のプロジェクト一式共有である。

### タブ

既存仕様を維持する。モバイルでは見た目だけシート／一覧にする。同じプロジェクトを 2 タブで開かない。再起動後は起動画面。

## プラットフォーム分岐

| 操作 | デスクトップ | モバイル |
|---|---|---|
| プロジェクト作成 | フォルダ選択 | 名前入力 → サンドボックス |
| プロジェクトを開く | フォルダ選択 | 端末内一覧 |
| データを渡す | フォルダそのもの、または手動 ZIP | 共有シートで `.bpsync.zip` |
| データを受ける | フォルダを開く、ZIP 取り込み | 共有／開く／取り込む |
| PDF・画像を選ぶ | OS 標準ダイアログ | ファイル選択・共有・カメラ |
| 保存 | プロジェクト内上書き | 同じ（サンドボックス上） |
| ホスト | Tauri のみ | Tauri モバイルでも可。バックグラウンドは保証しない |
| ウィンドウ枠 | カスタム chrome | 出さない |

ブラウザの `npm run dev` は現行どおりデモ用。ファイル共有もホストも無い。

## 権限とパッケージ

- iOS: 既存のカメラ／フォトライブラリ文言。共有・ファイル Open-in 用 UTI（`public.zip`, `com.adobe.pdf`）。最低 iOS 15
- Android: カメラ、通知は不要。共有の受け取り（`SEND` / `VIEW` for zip/pdf）。Scoped storage 前提で、共有で来たファイルはアプリ領域へコピーしてから読む
- Tauri capability を Android / iOS 用に分ける。デスクトップ用 `pick_*` をモバイルで呼んでも、HTML／共有経路へ倒す（今のエラー投げっぱなしはやめる）
- WebView の `getUserMedia` をモバイルでも許可する（Windows / Linux にあるカメラ許可の相当）

## 失敗時

- 共有 ZIP の作成失敗: 共有しない。理由を出す
- 受け取った ZIP が壊れている / `project.json` 不正: 取り込まない
- 同じ `id` の上書きを拒否した: 現状維持
- 注釈保存失敗: 共有もタブ切替も閉じるのも中断（既存）
- カメラ拒否: 日本語メッセージ（既存 `mapCameraError`）
- LAN 切断: ローカル編集は残す。一式はディスク上の最新を共有できる

## 実装範囲（方針）

コードは現行リポジトリのまま足す。新規アプリを切らない。

- I/O は `src/lib/utils/`。`.svelte` に `invoke` や座標計算を足さない
- プロジェクト一式の pack / unpack は zip ユーティリティとして単体テストする
- 共有シートは Tauri / プラグイン経由。コンポーネントはコールバックだけ
- ホーム・サイドバー・ツールバーは幅でレイアウトを分ける。ストアとプロトコルは共有
- モバイル capability・Android マニフェスト・iOS UTI を先に足してからコマンドを生かす

## テスト

- 一式 ZIP に `project.json`・図面・注釈（ピン含む）が入り、展開後に同じ `id` / `name` / `photoPins` が戻る
- `project.json` の無い ZIP は一式扱いしない
- パストラバーサルと `__MACOSX` を拒否する（既存 zip 規則）
- 同じ `id` は上書き確認なしに混ぜない
- 注釈 dirty のまま共有しようとしたら、先に persist し、失敗で共有しない
- `usesRfdFileDialog()` が false のときフォルダ選択 UI を出さない
- カメラ優先はモバイルで `environment`、デスクトップの USB 優先は壊さない
- LAN メッセージ型とチャンク再組立は現行テストを維持する

## 承認済みの判断（この仕様の固定事項）

- モバイルの正本はアプリ管理領域。外との橋はファイル共有
- 共有の正はプロジェクト一式 ZIP（`.bpsync.zip`）。中身はデスクトップと同じ木
- LAN は残すが、持ち帰り・バックアップ・ PC との往復の正ではない
- 描画エンジンは触らない。変わるのは「どこに置き、どう受け渡しするか」とモバイル chrome
- 写真ピンは JSON に載せたまま一式に含める。PDF へは焼かない
