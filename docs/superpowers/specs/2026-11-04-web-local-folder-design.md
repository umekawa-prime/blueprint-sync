# Web 版で端末フォルダに読み書きする（デモ脱却）設計

## 背景と意図

今の Web 版（`npm run build:web`）は動作確認用のデモで、ファイルは `src/lib/utils/webDemoFs.ts` のメモリ上にしかなく、リロードで消える。これを、ネイティブアプリと同じように **端末上のユーザーが指定したフォルダ** に読み書きする実用版にする。

対象は ChromeOS Flex と Windows。どちらもネイティブアプリでは困る事情がある（Flex は Linux 環境から内蔵カメラが使えない、Android アプリも動かない）。Web 版を静的ホスティング（Vercel / Cloudflare Pages など。図面データはサーバに置かない）で配り、ブラウザだけで現場の作業が完結することを目指す。

## ゴール

- Chrome 系ブラウザ（ChromeOS Flex の Chrome、Windows の Chrome / Edge）で、プロジェクトの作成・オープン・保存がユーザー指定フォルダに対して行える。リロード・ブラウザ再起動後も同じフォルダから続きができる。
- フォルダの中身は **ネイティブ版と同じ形式**（`project.json`、`図面/`、`工程表/`、`図面JWW/`、`.blueprint-sync/annotations/` など。`init_project_dir` と `projectIo.ts` が正）。同じフォルダを Windows ネイティブ版と Web 版のどちらで開いても同じ結果になる。
- 今ネイティブ版でできる取り込み・編集が Web からもできる：PDF 取り込み、画像貼り付け・写真ピン（カメラ撮影含む）、メモピン、課題・ノート・工程表、PDF 書き出し、CAD（JWW / JWC / DXF）取り込み、OneDrive リンク取り込み（後述の条件付き）。
- 最近使ったプロジェクトと、開いていたタブの復元が Web でも効く。
- **オフラインでも起動できる**（ユーザー決定）。一度オンラインで開けば、以後は電波のない現場でもリロード・再起動を含めて動く。
- **Web 版は自動保存する**（ユーザー決定）。書き込みのたびに数秒以内にフォルダへ保存し、未保存のまま閉じようとしたら警告する。
- プロジェクト一式（`.bpsync.zip`）の取り込みが Web でもできる（ユーザー決定。展開先は後述）。

## 非ゴール

- サーバ側の保存・アカウント・クラウド同期。図面データをサーバに置かない。サーバ処理は §6 の OneDrive 中継に限る。
- Safari / Firefox 対応（File System Access API のフォルダ選択がないため。非対応ブラウザには案内を出すだけ）。
- PC の別アプリを起動する機能（JW-CAD で開く、Cursor で開く、エクスプローラーで表示、Windows カメラアプリ起動）の Web 版。Web では非表示。
- LAN 同期（削除済み）。
- 同じプロジェクトフォルダを複数の場所（ネイティブ版と Web 版、ブラウザの複数タブ、同期フォルダ経由の複数端末）から同時に開いて編集すること（ユーザー決定：同時に開くのは 1 か所だけ）。衝突検出・統合は作らない。

## アンチゴール（動いても失敗とみなすもの）

- 保存したつもりのデータが、リロードやブラウザ再起動で黙って消える／古い内容に戻る。
- Web 版で保存したフォルダをネイティブ版で開くと壊れる・注釈が欠ける（逆も同様）。
- ネイティブ版（Windows / Android / iOS / Linux）の挙動が変わる・壊れる。
- 選んだフォルダの外に書き込む。

## 制約

- 実装は既存スタックの範囲：Svelte 5 + SvelteKit SPA（`adapter-static`、`ssr = false`）。AGENTS.md の規約に従う（I/O は `src/lib/utils/`、`.svelte` に I/O を足さない、ストアは `*.svelte.ts` クラス等）。
- ファイル I/O の分岐点は `src/lib/utils/projectIo.ts`（と `fileAccess.ts`）。今は `useWebDemoFs()` で「デモ用メモリ」と「Tauri `invoke`」に分かれている。ここに第 3 の実装「ブラウザのフォルダ（File System Access API）」を足す。呼び出し側（`projectActions.ts` など）はパス文字列ベースのまま動かせることが望ましい。
- File System Access API の性質：
  - フォルダ選択（`showDirectoryPicker`）はユーザー操作が必要。OS の重要フォルダなど一部は選べない。
  - 得た `FileSystemDirectoryHandle` は IndexedDB に保存でき、次回も使える。ただし読み書き権限は **次回訪問時にユーザー操作付きで再確認が要る** ことがある（`queryPermission` / `requestPermission`）。PWA としてインストールして「毎回許可」を選ぶと出なくなる場合がある。
  - HTTPS（または localhost）でのみ動く。カメラも同様。
- 静的ホスティングなので、ネイティブ（Rust）でしかできない処理はブラウザ内で完結させる必要がある。

## 決まったこと

ユーザーが決めたこと：

- 対象端末は ChromeOS Flex と Windows。
- データはブラウザ内ではなく、端末のユーザー指定フォルダに読み書きする（ネイティブ版と同じ考え方）。
- 画像貼り付け・データ読み込みなど、今の端末向け機能はすべて Web 経由で実行できる想定。
- CAD 取り込みと OneDrive 取り込みも Web 版で使えるようにする。
- オフラインでも起動必須。
- 同時に開くのは 1 か所だけ。
- Web 版は自動保存＋離脱時の警告。
- `.bpsync.zip` 取り込みは Web でも使う。展開先は、ユーザーが選んだ親フォルダの中にプロジェクト名のフォルダを新規作成する。既存フォルダを消すことはしない。

設計側（Claude）の判断としてユーザーに提示し、了承を得たこと：

- **CAD 取り込み**：既存の Rust 実装（`src-tauri/src/cad_dxf.rs`、`cad_pdf.rs`、`cad_font.rs`、`dxf_read.rs`、依存 `ezjww-core`）を WebAssembly 化し、ブラウザ内で変換する。変換ロジックを TS で二重実装しない。
- **OneDrive 取り込み**：まずブラウザから直接ダウンロードできるか（CORS）を試作で確認する。拒否される場合は、ホスティング先のサーバレス関数で小さな中継を立てる（ユーザー了承：サーバを立てるかどうかは設計側に一任）。詳細は §6。
- **カメラ**：Web では既存のブラウザ内カメラ（`CameraCapture.svelte` / `cameraCapture.ts`、`getUserMedia`）を使う。Windows カメラアプリ起動（`systemCamera.ts`）は Web では使わない。
- **最近使ったプロジェクト・タブ復元**：フォルダのハンドルを IndexedDB に保存して実現する。開く時に権限の再確認が出ることは許容する。
- **ネイティブ専用機能**（JW-CAD / Cursor / エクスプローラー表示 / Windows カメラ起動）：Web では UI ごと隠す。
- **デモ**：サンプルデータで試す今のデモは、実データ機能とは別に残す。

## 判断が必要な箇所と方針

### 1. パスとフォルダハンドルの対応

既存コードは `folder` / `path` を文字列で受け渡している（`RecentProject.path`、`OpenSession.folders` など）。Web では各プロジェクトフォルダのハンドルに安定 ID を振り、仮想パス（例：`fsa://<id>` を根とする `fsa://<id>/図面/A.pdf`）で表す。`projectIo.ts` の各関数は仮想パスを受け取ったら、ID からハンドルを引いてサブパスを辿る。

- ハンドルと ID の対応は IndexedDB に保存する（`RecentProject.path` には仮想パスを入れる）。
- サブパスに `..` や絶対パスが来たら拒否する（選んだフォルダ外への書き込み防止）。
- 仮想パスの形式・ID の作り方は実装側の判断に任せる。ただし `normalizeFsPath` など既存のパス比較ヘルパと整合させること。

### 2. 権限の再確認

起動時（タブ復元・最近使ったプロジェクト）にハンドルの権限が `prompt` 状態なら、自動で開こうとせず「このフォルダへのアクセスを許可」ボタンを出し、押されたら `requestPermission` する。拒否・ハンドル失効（フォルダが消えた等）の場合はエラーを出して一覧に残すか消すかを選べるようにする（文言・UI 詳細は実装側）。

### 3. 新規プロジェクト作成

ネイティブ版の「フォルダを選んでプロジェクトにする」挙動に合わせる。Web ではフォルダ選択で得たハンドルに `init_project_dir` 相当（`.blueprint-sync/annotations`、`図面`、`工程表`、`図面JWW` の作成）を行う。ネイティブ版で別の流れ（サンドボックス等）になっている箇所は `platform.ts` の分岐に Web を足して揃える。

### 4. Rust 依存の各コマンドの置き換え

`src/lib/utils` から呼んでいる Tauri コマンドのうち、ファイル系（`read_file_bytes`、`write_file_bytes`、`list_project_pdfs`、`list_project_files`、`init_project_dir`、`copy_file_into_folder`、`rename_file`、`delete_file`、`remove_dir_all`、`path_exists`、`pick_folder`、`save_pdf_file`、最近使った・セッション保存系）は、Web 実装を `projectIo.ts` / `fileAccess.ts` 内に用意する。挙動（PDF 一覧に出す拡張子、隠しフォルダ除外、名前衝突時の扱い）はネイティブ版の Rust 実装と同じにし、可能なものは TS 側の共通関数と単体テストで揃える。

`rename_file` は File System Access API に安定した移動 API がないため、コピー＋削除で実装してよい（大きいファイルでも整合が崩れない順序にする：書き込み完了を確認してから元を消す）。

### 5. CAD の WebAssembly 化

- `cad_bytes_to_pdf` を wasm 用の小さな crate（例：`src-tauri` と別の workspace member）から呼べるよう切り出す。Tauri 側も同じ crate を使う形にして、変換ロジックを 1 つに保つ。
- `cad_font.rs` は OS のフォントファイル（Windows の MS ゴシック等、Linux の Noto CJK）を読んでいる。wasm にはファイルシステムがないので、**フォントのバイト列を外から渡す** API に変える。Web 版はライセンス上再配布可能な日本語フォント（Noto Sans JP / BIZ UDゴシック等、OFL）を静的アセットとして置き、必要時に読み込む。ネイティブ版は従来どおり OS フォントを読む。
- `ezjww-core`（git 依存）が `wasm32-unknown-unknown` でビルドできるかは未確認。**最初に試作で確認する**。不可なら代替（フォーク・該当部分の切り出し）をユーザーに相談する。
- wasm とフォントは、実行は CAD を開いた時だけ行う（初回表示の処理を重くしない）。ただしオフライン起動が必須なので、ファイル自体は Service Worker で事前キャッシュしておく（§8）。

### 6. OneDrive

`oneDriveImport.ts` は `httpGet` を依存として受け取る作りなので、Web 用の実装を渡す。

- まずブラウザから直接 `fetch` を試す。CORS で通るならサーバは作らない。
- 通らない場合（設計側の判断）：ホスティング先のサーバレス関数（Vercel Functions / Cloudflare Workers など、配信先に合わせる）に、**OneDrive / SharePoint の共有 URL だけを受け付ける中継**を置き、Web 版の `httpGet` はそこを経由する。
  - 中継は状態を持たない。ダウンロードした内容を保存・記録しない。
  - 宛先は OneDrive / SharePoint の決まったドメインに限定し、それ以外は拒否する（誰でも使える中継＝オープンプロキシにしない）。
  - AGENTS.md の「`fetch('/api/...')` でバックエンドを足さない」に対する、ユーザー了承済みの例外。この中継以外にサーバ処理を増やさない。AGENTS.md にもその旨を追記する。
- OneDrive 取り込みはもともとネットが要る機能。オフライン時は「オンラインで実行してください」と出し、アプリの他の機能はサーバなしで動く状態を保つ。
- 中継も使えない場合に備え、「ブラウザでリンクを開いてダウンロード → ファイルとして取り込み」の導線も残す。

### 7. 非対応ブラウザ

`showDirectoryPicker` がない環境では、ホーム画面で「Chrome または Edge で開いてください」と案内し、デモだけ使えるようにする。

### 8. オフライン起動（PWA）

オフライン起動が必須なので、PWA 化（Web App Manifest ＋ Service Worker）は任意ではなく最初に入れる柱とする。

- アプリ本体（`build/` の HTML / JS / CSS）、pdf.js の worker、CAD の wasm、日本語フォントを事前キャッシュする。初回オンライン時にすべて取り終えたことを画面で分かるようにする（例：「オフラインで使えます」表示）。
- 新しい版を配信したら、次回オンライン起動時に裏で取得し、作業を中断しないタイミング（再読み込み時など）で切り替える。編集中に勝手にリロードしない。
- インストール可能にする（ChromeOS / Windows のランチャーやスタートメニューから開ける）。フォルダ権限の「毎回許可」にも効く。
- Tauri ビルドには Service Worker を入れない（ネイティブ版の挙動を変えない）。

### 9. 自動保存（Web のみ）

- 注釈・写真ピン・メモピン・課題・ノート・`project.json` の変更を検知し、短い間隔（数秒以内、まとめて 1 回）でフォルダへ書き込む。書き込み中に次の変更が来たら、終わってからもう一度書く（取りこぼし・追い越しをしない）。
- 未保存の変更がある状態でページを閉じる・リロードする時は `beforeunload` で警告する。タブが裏に回った時（`visibilitychange` → hidden）にも即時保存を試みる。
- 保存状態（保存中／保存済み／失敗）をステータスバー等で見えるようにする。権限切れ・容量不足などで失敗したら、黙らずに知らせる。
- ネイティブ版の保存タイミングは変えない。自動保存は Web 実装側（または `isTauriRuntime()` で分けた層）に置く。
- 写真が JSON に埋め込まれているため注釈ファイルが大きくなりうる。自動保存で書き込みが重くならないよう、変更のあった図面の注釈ファイルだけを書く。

### 10. 同時オープンの扱い

同時に開くのは 1 か所だけと決めたので、衝突検出はしない。ただしブラウザの複数タブで同じフォルダを開いたときは、自動保存同士で上書きし合わないよう、Web Locks（または BroadcastChannel）で後から開いたタブに「別のタブで開いています」と表示し、編集させない。

### 11. プロジェクト一式（`.bpsync.zip`）の取り込み

今の `importIncomingFile` → `installBundle` はサンドボックス配下に `meta.id` 名のフォルダを作って展開し、上書き時は `removeDirAll` で消している。Web ではサンドボックスがないので、取り込み時に保存先の親フォルダを選んでもらい、その中にプロジェクト名（衝突したら連番などで別名）のフォルダを **新規作成** して展開する。既存フォルダの削除・上書きは Web では行わない。展開したフォルダは最近使ったプロジェクトに登録する。

## 実装側に任せること

- 仮想パスの具体的な文字列形式、IndexedDB のスキーマ名、ハンドル ID の生成方法。
- 権限確認・エラー表示の文言と見た目（既存の Tailwind・トーストの流儀に合わせる）。
- wasm のビルド手段（`wasm-pack` / `wasm-bindgen` 直接など）と、`npm run build:web` への組み込み方。
- Service Worker の作り方（`vite-plugin-pwa` を使うか、SvelteKit 標準の `src/service-worker.ts` で書くか）。
- 自動保存の具体的な間隔。
- OneDrive 中継を置くサーバレス基盤の選定（配信先に合わせる）。

## 検証

- 単体テスト（Vitest）：Web 用ファイル実装は `FileSystemDirectoryHandle` をメモリ上のモックで差し替えてテストする（パス解決、`..` 拒否、一覧のフィルタ、リネーム、初期化フォルダ構成）。既存の `projectIo.test.ts` / `projectActions.test.ts` の流儀に合わせる。
- 互換性：Web 版で作ったプロジェクトフォルダをネイティブ版（Windows）で開き、図面・注釈・写真ピン・メモピン・課題が同じに見えること。逆方向も確認。
- 実機：ChromeOS Flex の Chrome と Windows の Chrome / Edge で、フォルダ選択 → 編集 → リロード → 権限再確認 → 続きの編集、カメラ撮影、CAD 取り込み、PDF 書き出しまで通す。
- オフライン：一度オンラインで開いた後、ネットを切ってアプリを起動 → プロジェクトを開く → 編集 → CAD 取り込み → 保存、まで通る。
- 自動保存：編集直後に F5 / タブを閉じる / ブラウザを強制終了しても、数秒前までの編集がフォルダに残っている。
- 複数タブ：同じフォルダを 2 つ目のタブで開くと編集できない表示になる。
- ネイティブ版の回帰：`npm test`、`npm run check`、`npm run tauri dev` で既存の動作が変わっていないこと。
