# 画像フォルダとピン上の注釈、ストロークごとの自動保存

日付: 2026-09-08  
対象: Blueprint Sync（図面ピン写真・注釈の永続化）

## 背景

現場写真は図面上のピンとして挿入できるが、開いても見るだけでペンやテキストが書けない。画像は注釈 JSON の data URL に埋まっており、プロジェクトの `図面/`・`工程表/` と並ぶ実ファイルになっていない。ペンや挿入も「保存」を押すまでディスクに残らない。

## ゴール

- ピンを開いた画面で、PDF と同じペン／テキスト（Shift＋クリック直線と先端形状を含む）が使える
- 元画像は残し、線・テキストは重ねて保存する。あとから足したり消したりできる
- 画像ファイルはプロジェクト直下の `画像/`（`図面/`・`工程表/` と同一階層）に置く
- ペン1本・テキスト配置・画像挿入・ピン上の記入・削除や移動の確定のたびに、注釈 JSON（と新規画像ファイル）をディスクへ書く
- ツールバーの「保存」は、これまでどおり PDF 本体へ注釈を焼き込む。プロジェクトデータはボタンを待たない

## やらないこと

- 写真をサイドバーの単独ページとして開く
- 図面キャンバス上に画像オブジェクトを直接置く
- 注釈を JPEG に焼き込んで元画像を捨てる
- サムネイルをフル解像度ファイルから毎回作る（小さい data URL は残す）
- LAN 同期で既存クライアントが data URL ピンだけを理解する互換レイヤの長期維持（開いたときに `画像/` へ書き出す）

## フォルダ

```
プロジェクト/
  図面/
  工程表/
  画像/{ピンID}.jpg
```

撮影・挿入のたびに `画像/` が無ければ作る。ファイル名はピン ID。元画像は上書きしない。ピン削除時は対応する JPEG と、そのピンのオーバーレイを消す。

## ピンとオーバーレイ

図面ごとの注釈 JSON（現行パス）に載せる。

ピン:

- `id`, `nx`, `ny`, `title` は今どおり
- `thumbnailDataUrl` は小さいプレビュー用に残す
- `imageDataUrl` は新規では書かない
- `imageRel` は `画像/{ピンID}.jpg`

オーバーレイ:

- 同じ JSON の `photoOverlays[ピンID]` に Fabric オブジェクト（PDF 注釈と同じシリアライズ）
- 写真キャンバス上の座標。PDF ページの `byPage` とは混ぜない

data URL だけの古いピンは、開いたときに `画像/` へ書き出して `imageRel` を付け、以降は同じ扱い。

## ピンを開いた画面

拡大表示を、写真の上に載る Fabric キャンバスにする。開いているあいだ、ツールバーの選択／ペン／テキストは写真に効く。Shift 直線も同じ。Esc またはモーダル外クリックで閉じ、ツールは再び PDF に効く。閉じる操作では追加の保存をしない（直前のストロークは既に書いてある）。図面上のピン移動・タイトルは今どおり。

## 自動保存

対象: フリーハンド1本の確定、Shift 直線の確定、テキスト配置、画像挿入・撮影（JPEG を書いてから JSON）、写真上の線・テキスト、オブジェクトの削除・移動の確定。

書き込みはキューして1本ずつ順に実行する。失敗したらステータスに出し、メモリ上の注釈は残す。

## 同期・共有

プロジェクト ZIP に `画像/` を含める。LAN 同期はピンメタ・オーバーレイ JSON に加え、新規 JPEG も送る。PDF の `annotation` メッセージとは別に、ファイルバイトを既存のチャンク送信に乗せる。

## 権限

デスクトップで `画像/` へ書く。新しい Tauri コマンドは増やさず、既存の `write_file_bytes` / ディレクトリ作成をプロジェクトフォルダ配下で使う。
